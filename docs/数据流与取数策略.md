# 数据流与取数策略

## 1. 用友 U8 V18.0 后台数据结构概览

用友 U8 的财务与业务数据存放在 SQL Server 的若干库中，常见库与表如下（实际名称以现场为准，需在配置中设定）：

| 库 | 用途 | 常见表 |
|----|------|--------|
| `UFDATA_xxx_2026` | 年度账数据库（xxx为账套号） | 总账、明细账、辅助账 |
| — 总账凭证 | GL | `GL_accvouch` 凭证分录、`GL_accsum` 科目汇总、`GL_accass` 辅助汇总 |
| — 科目 | GL | `Code` 科目档案 |
| — 往来 | AP/AR | `Ap_detail`、`Ap_Detail`、`PURBILL`、`Invoice` |
| — 存货 | ST | `ST_CurrentStock` 现存量、`ST_Total` 出入库汇总、`RdRecord01/32` 收发记录 |
| — 存货档案 | ST | `Inventory` 存货档案 |
| — 固定资产 | FA | `fa_Cards` 卡片、`fa_Departments` |
| — 工资 | WA | `wa_GZData` |

> 注意：上述表名为用友通用命名，**具体字段与表名必须以现场 UFDATA 库为准**。所有查询集中在 [`queries/u8.py`](queries/u8.py:1)，便于按现场调整。

## 2. 取数总体流程

```
开始
  │
  ├─① 建立连接（pyodbc，复用单一连接）
  │
  ├─② 读取上下文参数：会计期间（年、月）
  │
  ├─③ 批量预取公共数据（对同一期间一次性查询）
  │     · 科目余额汇总（GL_accsum）
  │     · 存货现存量（ST_CurrentStock）
  │     · 应收应付明细（Ap_detail / AR）
  │     · 固定资产卡片（fa_Cards）
  │     …… 结果放入 context.cache
  │
  ├─④ 按 LK 代码顺序逐表生成
  │     for code in selected_reports (按序):
  │         report.fetch(context)   # 优先用缓存，缺则补查
  │         report.write(sheet, context)
  │         更新进度条
  │
  └─⑤ 另存为一个多表页 .xls 文件
```

## 3. 为什么"顺序生表 + 共享缓存"

| 问题 | 方案 |
|------|------|
| 表页多（43）、指标多、查询慢 | **按序生成**，进度可见，避免长时间无响应；单表失败不影响后续 |
| 多张表依赖同一 U8 表（如 GL_accsum 被多表使用） | **一次性批量取数** 到 `context.cache`，各表复用，避免 N 次重复查询 |
| 勾稽关系要求主表与明细表一致 | 按 LK01→LK33 顺序，主表取数时明细数据已就绪 |
| 远程连接网络往返开销 | 复用单连接；批量查询用 `WHERE 期间 IN (...)` 减少往返 |

## 4. 缓存键设计

`context.cache` 为一个字典，键采用 `"库.表:期间:参数"` 命名，例如：
- `"GL_accsum:2026-05"` → 该月科目汇总
- `"ST_CurrentStock:2026-05"` → 该月现存量
- `"fa_Cards:2026-05"` → 固定资产卡片

报表类通过 `context.get_cache(key)` / `context.set_cache(key, data)` 访问。

## 5. 性能措施

1. **连接复用**：全局单一 pyodbc connection。
2. **批量查询**：一次取整月数据，而不是逐科目/逐存货查询。
3. **只取所需列**：SQL 明确列出字段，避免 `SELECT *`。
4. **用索引字段过滤**：期间（`iperiod`/`iyear`）、科目编码（`ccode`）等。
5. **可选 pandas**：批量数据放入 DataFrame 便于分组聚合。
6. **SQL 超时与重试**：设置 `timeout`，对远程连接增加重试。

## 6. 核对与排错设计

- **SQL 审计**：每次查询记录 SQL 文本、参数、耗时、返回行数到 `logs/sql_audit.log`。
- **中间结果导出**：可将 `context.cache` 导出为 Excel，供与用友前台逐项比对。
- **勾稽校验**：`verify/reconciliation.py` 实现模板"主要勾稽关系"表的 45 条公式。
- **前台对照**：用友前台有"账表查询"（余额表、明细账），本工具提供同口径 SQL，便于比对差异定位。

## 7. 待确认的现场参数（开发前需向财务/IT确认）

1. U8 账套号与年度库名（如 `UFDATA_001_2026`）。
2. 会计期间的具体年月。
3. 服务器实例名、端口、认证方式（SQL 认证 / Windows 认证）。
4. 各报表指标与 U8 字段的**精确对应关系**（需逐一确认，这是核心工作量）。
5. 用友数据是"已记账"口径还是"含未记账凭证"口径。
