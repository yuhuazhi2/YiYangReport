## 一、先跑起来：程序的入口在哪里？

一切都从 [`main.py`](../main.py) 开始。它做的事情非常少，但很关键：

```text
main.py
  │
  ├─ ① init_logging()        初始化日志系统（往 logs/ 写文件）
  ├─ ② load_config()         读取上次保存的配置（连接信息、期间、输出目录）
  ├─ ③ 若有配置 → 直接进主窗口 MainWindow
  │   若无配置 → 先弹 ConnectionDialog 让用户填数据库连接
  └─ ④ app.exec()            进入 Qt 的"事件循环"，界面开始响应用户操作
```

【新手必学】**什么是"事件循环"？**
你写的界面代码，本质上不是"从头跑到尾"的脚本，而是"待命"状态。
`app.exec()` 会让程序停在这里，等着用户点按钮、敲键盘，
每来一个事件，Qt 就去找对应的方法（比如点击 → `_on_xxx`）来执行。
所以你会看到：界面代码里全是 `_on_` 开头的方法，却没人去主动调用它们——
**是 Qt 在调用它们**。

【关键概念：`QApplication` 只能有一个】
一个程序只能创建一个 `QApplication` 实例。它是所有界面的"根"。

## 二、数据是怎么流动的？（全流程主线）

这是本项目**最核心的一张图**。看懂它，整个项目就懂了一半：

```text
        ┌─────────────────────────────────────────────────────────┐
        │                      用户界面层 (ui/)                    │
        │  ConnectionDialog  →  ConnectionInfo（连接参数）          │
        │  ReportSelectDialog →  selected_codes（勾选的LK代码列表） │
        │  MainWindow        →  进度条 / 日志 / 核对结果            │
        └───────────────────────────┬─────────────────────────────┘
                                    │ 点击"生成"
                                    ▼
        ┌─────────────────────────────────────────────────────────┐
        │              应用服务层 (app/generator.py)               │
        │  ReportGenerator.generate(codes)                        │
        │    · 打开 Excel 模板（ExcelEngine）                       │
        │    · 只保留选中的表页                                     │
        │    · 逐个报表：new → fetch(取数) → write(填表)            │
        │    · 汇总结果 → GenerateResult                           │
        └──────┬────────────────────────────────────┬─────────────┘
               │                                    │
               ▼                                    ▼
   ┌───────────────────────┐          ┌───────────────────────────┐
   │  报表层 (reports/)     │          │   数据访问层 (core/db.py)  │
   │  LK01Report ...       │◄────────►│   Database.query(sql)      │
   │  · fetch(): 调 SQL    │  取数据   │   · pyodbc 连接 SQL Server │
   │  · write(): 写单元格  │          │   · 返回 rows             │
   └───────┬───────────────┘          └───────────────▲───────────┘
           │                                          │
           │ 写单元格                                  │ SQL 从哪来？
           ▼                                          │
   ┌───────────────────────┐          ┌──────────────┴────────────┐
   │ Excel 引擎 (excel_engine)│        │  SQL 定义 (queries/u8.py)  │
   │  win32com 驱动真 Excel  │        │  每个函数返回 (sql, params) │
   └───────────────────────┘          └───────────────────────────┘
```

【新手必学】记住这条链路上"三种角色"的职责边界：

| 角色 | 目录 | 职责 | 不该做的事 |
|------|------|------|-----------|
| 界面 | `ui/` | 收用户输入、显示结果 | 不写 SQL、不操作 Excel |
| 编排 | `app/` | 把各步骤串起来、报进度 | 不关心具体某张报表怎么填 |
| 报表 | `reports/` | 一张报表的取数与填表逻辑 | 不管界面、不管线程 |
| 数据 | `core/`+`queries/` | 连库、取数、驱动 Excel | 不管业务、不管界面 |

【新手难点】**为什么要分这么细？**
因为如果所有代码写在一个文件里，等到要改第 15 张报表时，
你会在 3000 行代码里找不到东南西北。分层之后：
- 改界面 → 只动 `ui/`
- 改 SQL → 只动 `queries/`
- 加报表 → 只动 `reports/`

## 三、核心模块逐个讲（按调用顺序）

### 1. [`config/settings.py`](../config/settings.py) —— 记住用户的设置

【新手必学】用 `@dataclass` 定义配置，是 Python 的省事写法：

```python
@dataclass
class ConnectionInfo:
    server: str = "localhost"
    port: int = 1433
    username: str = ""
    ...
```

它自动帮你生成了 `__init__`，不用手写一堆 `self.server = server`。
本模块的关键点：
- `load_config()` / `save_config()`：读写配置文件（下次启动记得上次设置）
- `ensure_dirs()`：确保 `logs/`、`output/` 等目录存在
- **密码处理**：SQL 密码用 Fernet 加密后再落盘（不存明文）

### 2. [`core/logging_setup.py`](../core/logging_setup.py) —— 出事了能查

- `get_logger(__name__)`：**每个模块都要这样取 logger**
- `RotatingFileHandler`：日志文件写满自动切割（如 5MB 切一个），防止无限变大
- `SQLAudit.record()`：专门记录"跑了哪条 SQL、耗时多少、返回几行"
- `timed_query`：上下文管理器，自动统计 SQL 耗时

【新手必学】日志级别从小到大：`DEBUG < INFO < WARNING < ERROR < CRITICAL`。
平时记 INFO，用户小事记 WARNING，出错记 ERROR。

### 3. [`core/db.py`](../core/db.py) —— 唯一碰数据库的地方

`Database` 类的常用方法：

| 方法 | 用途 |
|------|------|
| `connect()` | 建立连接 |
| `query(sql, params)` | 查多行，返回列表 |
| `query_dict(sql, params)` | 查多行，返回字典列表（列名→值） |
| `query_one()` / `scalar()` | 只取一行 / 只取一个值 |
| `list_tables()` / `list_columns()` | **核对现场表结构**（非常重要！） |

【新手必学】SQL 注入防护的核心：**永远用 `?` 占位符传值**，
绝不把用户输入直接拼进 SQL 字符串。详见 [`queries/u8.py`](../queries/u8.py) 顶部注释。

### 4. [`core/template.py`](../core/template.py) —— 识别模板里的表页

- `TemplateParser`：打开 .xls 模板（用 xlrd 只读方式）
- `SheetInfo`：描述一个表页（名称、LK 代码、标题所在行等）
- `CODE_PATTERN`：用正则从表页名里抠出 `LK01` 这类代码

【新手必学】正则表达式基础：
- `\d` 匹配一个数字，`\d+` 匹配一或多个数字
- `[A-Z]` 匹配一个大写字母
- `LK(\d+)` 能匹配 "LK01" 并**捕获**出 "01" 这部分

【重要结论】本项目**以 LK 代码为准**来标识表页（代码+名称组合区分）。

### 5. [`core/excel_engine.py`](../core/excel_engine.py) —— 真正操作 Excel

这是全项目最"重"的模块，因为它用 win32com 驱动**本机安装的真 Excel**。

【新手必学】为什么不用 openpyxl 直接写？
因为模板是 **.xls（97-2003 老格式）**，且含公式、合并单元格、
复杂格式。openpyxl 只处理 .xlsx，无法完美保留 .xls 格式。
只有"用真 Excel 打开 → 另存"才能做到分毫不差。

关键用法：
```python
with ExcelEngine(template_path) as engine:   # 进入时打开 Excel
    engine.keep_only(["LK01", "LK05"])       # 只保留选中表页
    hook = engine.sheet("LK01")              # 拿到某个表页的操作句柄
    hook.set_cell(8, 3, "100.00")            # 写单元格
    engine.save_as(out_path, fmt="xls")      # 另存（绝不动原模板）
```

【新手难点】为什么一定要用 `with`（上下文管理器）？
因为 Excel 是**外部程序**。万一中途报错而没有关闭，
电脑里就会残留一个看不见的 EXCEL.EXE 进程，越积越多、越跑越慢。
`with` 能保证"无论成功失败，退出时都执行关闭"。

### 6. [`core/context.py`](../core/context.py) —— 报表的"工具箱"

`ReportContext` 是传给每张报表的"随身工具包"，装着：
- `db`：数据库连接（复用，不重复连）
- `period`：会计期间（年、月）
- `config`：配置
- `report_data`：各报表之间共享的中间数据
- **缓存**：同样的一条 SQL 取过一次，第二次直接用缓存（键形如 `"库.表:期间:参数"`）

【新手必学】`@dataclass` 里的 `field(default_factory=list)` 是干什么的？
因为**可变默认值是个陷阱**：
```python
@dataclass
class A:
    items: list = []          # ❌ 错误！所有实例会共享同一个列表！
    items: list = field(default_factory=list)   # ✅ 正确，每个实例独立
```
这是 Python 新手最容易踩的坑之一，务必记住。

### 7. [`reports/base.py`](../reports/base.py) —— 所有报表的"父类"

用到了两个重要概念：

【新手必学】**抽象基类（ABC）与 `@abstractmethod`**
```python
class BaseReport(ABC):
    @abstractmethod
    def fetch(self, ctx): ...
    @abstractmethod
    def write(self, hook, ctx): ...
```
意思是："想当我的子类，就必须实现 `fetch` 和 `write`，
否则不让你创建对象。"这强制了所有报表结构统一。

【新手必学】**模板方法模式**
`BaseReport.generate(hook, ctx)` 已经写好了固定流程：
```python
def generate(self, hook, ctx):
    data = self.fetch(ctx)     # ① 取数（子类实现）
    self.write(hook, ctx, data) # ② 填表（子类实现）
    self.verify(ctx, data)      # ③ 校验（可选）
```
子类只需填空，不用管流程——流程由父类定死，这就是"模板方法"。

### 8. [`reports/registry.py`](../reports/registry.py) —— 报表"花名册"

【新手必学】**装饰器 + 注册表模式**
```python
@register("LK01")
class LK01Report(BaseReport):
    ...
```
`@register("LK01")` 会在类定义的那一刻，自动把 `LK01Report` 登记到
全局字典 `_REGISTRY` 里。之后：
- `create_report("LK01")` → 就能造出对应的报表对象
- `build_report_set(["LK01","LK05"])` → 批量造
- 想加新报表？**不用改这个文件**，只要在别处写个 `@register` 的类即可。

这叫**开闭原则**：对扩展开放，对修改关闭。

### 9. [`reports/lk01_sample.py`](../reports/lk01_sample.py) —— 一张报表的样板

这是**你写新报表时应该参考的模板**。文件里有一节
「★新增一张报表的标准步骤（新手必读）★」六步法，照做即可。

### 10. [`app/generator.py`](../app/generator.py) —— 总指挥

`ReportGenerator.generate(codes)` 的主循环（简化版）：

```python
with ExcelEngine(template) as engine:
    engine.keep_only(selected_codes)
    for i, rep in enumerate(reports, start=1):
        self._report(i, total, rep.code, f"正在生成 {rep.code}")  # 报进度
        try:
            hook = engine.sheet(rep.code)
            rep.generate(hook, ctx)
            result.generated_codes.append(rep.code)
        except Exception as exc:
            # 关键：单张报表失败，不影响其他报表！
            result.failed[rep.code] = str(exc)
    engine.save_as(out_path, fmt="xls")
```

【新手必学】**为什么 `try` 写在 for 循环里面？**
写在循环外面的话，第 5 张报表一出错，后面 38 张全都不生成了。
写在里面，就能做到"这张失败，记下来，继续下一张"。
这叫**故障隔离**，对批量任务特别重要。

【新手必学】`progress` 回调：`ReportGenerator(progress=my_func)`，
每处理一张表就调一次 `my_func(i, total, code, msg)`。
UI 就是靠它更新进度条的。

### 11. [`verify/reconciliation.py`](../verify/reconciliation.py) —— 对账工具

- `CheckItem`：一条勾稽关系（如"资产总计 = 负债 + 所有者权益"）
- `CheckResult`：核对结果，用 **三态** 表示：
  - `True` = 通过
  - `False` = 不通过
  - `None` = 数据不足/无法判断（**注意不是 False！**）

【新手必学】为什么用 `Optional[bool]`（即 `bool | None`）而不是单纯的 bool？
因为"没数据"和"数据不对"是两回事：
前者不该报警（可能本来就没生成那张表），后者必须报警。
用 `None` 表示"未知"，能避免误报。

【新手难点】表达式求值：核对公式存成字符串（如 `"a == b + c"`），
用受限的 `eval()` 求值。文件里讲了如何用白名单防止恶意代码执行。

### 12. [`ui/`](../ui/) 目录 —— 用户看到的一切

- [`ui/connection_dialog.py`](../ui/connection_dialog.py)：连接配置对话框
  （含"测试连接"、Windows 认证/SQL 登录切换、最近连接记录）
- [`ui/report_select_dialog.py`](../ui/report_select_dialog.py)：表页勾选框
  （全选/反选、搜索过滤、记住上次勾选）
- [`ui/main_window.py`](../ui/main_window.py)：主窗口
  （**线程 + 进度条 + 日志**，全项目界面部分的重头戏）

【新手必学】UI 层三大必会概念（详见各文件顶部注释）：
1. **布局 Layout**：不要手算坐标，用 QVBox/QHBox/QForm 自动排
2. **信号与槽**：`button.clicked.connect(self._on_click)`
3. **QThread 后台线程**：耗时任务放后台，通过信号回报进度

【新手难点】为什么子线程不能直接改界面？
因为 Qt 的界面控件不是线程安全的，跨线程直接改会随机崩溃。
正确做法：子线程只**发信号**，主线程收到信号后再改界面。
详见 [`ui/main_window.py`](../ui/main_window.py) 中 `GenerateWorker` 的注释。

## 四、我想加一张新报表，该动哪些文件？（实操路线）

这是你**最常用**的操作。以"新增 LK02 表"为例：

```text
第 1 步  queries/u8.py
         若 LK02 需要新的数据，在这里加一个取数函数，
         返回 (sql, params)。若现有函数够用，跳过这步。

第 2 步  reports/lk02_xxx.py      ← 新建文件
         @register("LK02")
         class LK02Report(BaseReport):
             def fetch(self, ctx):
                 sql, params = 某个取数函数(...)
                 return ctx.db.query(sql, params)
             def write(self, hook, ctx, data):
                 hook.set_cell(行, 列, 值)      # 按模板要求填

第 3 步  reports/__init__.py      ← 改一行
         加一句 import，让上面那个类被"加载"到（否则 @register 不会执行）

第 4 步  运行程序验证
         主界面 → "选择表页并生成" → 勾上 LK02 → 生成 → 检查结果
```

【新手必学】为什么第 3 步的 import 不能省？
因为 `@register` 装饰器只有在**这个类被 Python 加载**时才会执行。
如果没人 import 它，Python 根本不知道有这个类存在，注册表里自然没有它。

## 五、调试与核查：出问题了怎么办？

### 1. 数据不对，怎么查明细？

```text
主界面 → "查看 SQL 审计" → 打开 logs/sql_audit.log
```
里面记录了每次取数的：SQL 语句、参数、耗时、返回行数。
拿这些 SQL 去 U8 前台或数据库里跑一遍，就能对比是"取数错"还是"填表错"。

### 2. 怀疑表结构不对？

用 [`core/db.py`](../core/db.py) 的 `list_columns("GL_accsum")`
看看这个表真实的字段名有哪些。**这是部署到现场第一步要做的事！**

### 3. 单元测试式的手工验证

```python
from core.template import load_template_catalog
catalog = load_template_catalog("2026版新修订企业财务报模板.xls")
for s in catalog:
    print(s.code, s.name)
```

### 4. 勾稽关系核对怎么看？

生成完成后，日志区会打印核对报告。三态含义：
- ✅ 通过 → 数据自洽
- ❌ 不通过 → 有报表取数/填表可能出错，重点查
- ⚠️ 无法判断 → 相关表页没生成，或公式变量取不到

## 七、术语速查表（给初学者）

| 术语 | 通俗解释 |
|------|---------|
| 抽象基类 (ABC) | "只定规矩、不干实事"的父类，强迫子类实现某些方法 |
| 装饰器 | 写在函数/类上面 `@xxx` 的"外挂"，能悄悄加功能 |
| 上下文管理器 | `with ...:` 语法，保证"进门开门、出门关门"，如关闭文件/Excel |
| 信号与槽 | Qt 的事件机制：控件发"信号"，方法作"槽"来接 |
| 回调函数 | "回头再叫你"的函数，你把它交给别人，别人在合适时机调用 |
| 数据类 (dataclass) | 专用来装数据的类，自动生成 `__init__` 等方法 |
| 缓存 | "算过一次就记住"，下次同样请求直接给结果，省时间 |
| 勾稽关系 | 财务报表之间必须成立的等式关系，用来交叉验证数据正确性 |
| 表页 | Excel 里的一个 Sheet（工作表） |
| 账套 | 用友里的一套账（一个独立的核算主体，如"XX公司"） |
| 年度库 | 用友 U8 里形如 `UFDATA_001_2026` 的数据库，某账套某年的数据 |
| 占位符 `?` | SQL 里给"值"预留的位置，防止 SQL 注入 |

## 八、需要特别注意的"坑"清单

读完代码后，请特别留意这些容易出错的地方：

1. **绝不修改模板文件**：所有输出都用 `save_as` 另存到输出目录
2. **`.xls` 格式依赖真 Excel**：目标机器必须装 Excel，否则生成失败
3. **U8 字段名必须现场核对**：[`queries/u8.py`](../queries/u8.py) 里的表名字段
   是通用命名，**不一定**和客户现场一致
4. **可变默认值陷阱**：用 `field(default_factory=list)`，别用 `= []`
5. **子线程不能碰界面**：只能发信号
6. **SQL 判断空值用 `IS NULL`**，不能写 `= NULL`
7. **对字段用函数会让索引失效**：`YEAR(dDate)` 这类写法要注意性能
8. **单表失败不能影响全局**：`try` 要写在循环内
9. **勾稽核对的三态**：`None` ≠ `False`，不要混用
10. **Excel 进程残留**：务必用 `with ExcelEngine(...)` 保证关闭

## 九、一张图总结

```text
用户点"生成"
     │
     ▼
MainWindow._start_generate()          ← 界面层：收集参数、锁按钮
     │ 起后台线程 GenerateWorker(QThread)
     ▼
ReportGenerator.generate(codes)       ← 应用层：总编排
     │
     ├─ ExcelEngine(template)         ← 引擎层：打开 Excel，另存
     │

            │     └─ ctx.db.query()   ← 数据层：pyodbc → SQL Server
            └─ rep.write(hook, ctx)   ← 报表层：往单元格填数

     ▼
GenerateResult ──信号──► MainWindow._on_finished()
                                          ← 界面层：更新进度、打印日志
```
